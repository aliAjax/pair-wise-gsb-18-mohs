# hxwl-04 牙体牙髓科 · 知情同意核对台

按**患者与牙位**管理根管治疗知情同意书的核对看板，解决“一份笼统签字走到底、更换牙位开髓或加做显微治疗仍沿用旧同意”的问题。

## 核心规则

- 一份同意书对应「一位患者 × 一颗牙」，独立记录版本、签署日期、代办人与**四项风险逐项确认**。
- 治疗计划变化（更换开髓牙位、加做显微根管治疗等）后，同意书变为「待重新确认」；**重新签署前不能登记开髓或充填**（纯函数门禁 `canRegisterStep` 强制拦截，包含撤销、未签署、风险未全选、未开髓先充填等情况）。
- 版本只追加、生成即锁定：**撤销 / 补签 / 更正都新建版本**，保留原因以及每个字段的旧值、新值；旧版本不改写。
- 数据持久化到浏览器 localStorage，重开页面后状态与完整版本记录仍可见。

## 分层结构

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 资料 | `src/data/` | 类型、固定目录（四项风险 / 计划项目）、演示种子数据 |
| 判断 | `src/domain/` | 纯函数规则（状态、门禁）、reducer 状态迁移、读模型 |
| 存储 | `src/storage/` | localStorage 仓储与结构校验 |
| 表示 | `src/ui/` | 看板、牙位卡片、详情抽屉、弹窗 |
| 编排 | `src/state/` | React hook，连接判断层与存储层 |

关键文件：

- `src/domain/policy.ts`：同意书状态（未签署 / 待重新确认 / 已签署 / 已撤销）与开髓、充填登记门禁。
- `src/domain/reducer.ts`：签署、计划变化、补签、更正、撤销、步骤登记的全部写入规则与留痕。
- `src/storage/repository.ts`：读取、校验、保存、重置。
